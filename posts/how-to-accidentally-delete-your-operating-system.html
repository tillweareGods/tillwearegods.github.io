How to accidentally delete your file system in Linux

In a Linux operating system a single line of code could delete the whole system. The files, the configurations, system files could be permanently erased. Consider it like right click, deleting a folder in Windows but instead it's the whole operating system. We'll be looking into the underlying qualities of the operating system that allow this interesting thing to happen.

So, what's Linux?

Linux is an operating system. An operating system is a piece of software that manages resources, allocates memory and storage space, and handles resource allocation so multiple programs can run on our system. As an operating system, Linux does some things a bit differently than Windows and Mac (Apple).

Allocating resources gives programs CPU time, allowing them to do computations, gives them storage so they can save what they need to a storage device and load what they need from that device, and gives them memory so they can hold information while they do the computation.

The Linux file system

Linux is organized in a tree structure where everything is under the root directory (a directory is a folder in the Windows world), denoted by /. So everything, including your wallpaper configuration, the programs you installed, and your username and password, is somewhere under the root directory, and the sign for that main tree is /.

This allows you to access anything by navigating down the tree to the location you want. This is why you'll most likely hear the phrase "Everything in Linux is a file" , it means you can access anything by directly navigating to it and opening it. For example, if you want to navigate to your Downloads folder, you'd type:

cd /home/john/Downloads

cd means "change directory", we're just telling it to navigate to the directory that follows. It'll go down the tree starting from the root, which we said was denoted by /. You don't need to memorize any of these commands; you just need to understand how the tree works.

How is it different from Windows?

You might be thinking, "We can navigate through folders on Windows and Mac too." Yeah, you can open a folder and open some files, but the main difference is that you can't look through anything other than the files Windows allows you to view, or you might need custom software to view the files.

For example, on every operating system, either Windows or Mac, we have usernames and passwords required for logging into the computer. In the Linux operating system, those usernames and passwords can be accessed as if you were opening a text file. If you use the command:

cat /etc/passwd

you can see the usernames that are registered on that device. cat is used to print the contents of a file. So if we say cat example-text.txt, it will print the contents of the example-text.txt file we have in our current folder. When we did cat /etc/passwd, we're printing everything inside /etc/passwd.

You can also view the hashed passwords (passwords are not stored as plain text files; they are transformed so that even if they leak, it's harder to use them, the transformation is called hashing, and it's a one-way transformation) for the accounts on that device by typing:

cat /etc/shadow

which will give you the hashed passwords. In Windows, user account information is stored in the Security Accounts Manager (SAM) database for local accounts. The SAM is not a text file and cannot be opened and read like /etc/passwd, but Windows provides tools to view user information instead of reading a text file.

Can you delete the operating system?

Now for the fun part, remember when we said that "Everything in Linux is a file"? We do lots of stuff to files; for example, if we had a text file, we can rename it, we can add contents to it, we can also overwrite existing content, and, most importantly, delete it. If our original claim was correct, we should be able to delete everything, right?

We said the operating system had a tree-like structure where there is the root directory, a root branch, and everything can be accessed by going down to the branches, so that would mean if we cut off the root branch, everything inside it should get deleted.

Historically, the command used was:

rm -rf /

where rm means remove, -r stands for recursively, -f stands for force delete without prompting so that it doesn't prompt us, and / is the directory we want to delete.

In modern systems, there is a safety feature called --preserve-root that is enabled by default. On modern systems, rm -rf / would produce an error to prevent the accidental deletion of the entire system. If we intentionally wanted to delete the root directory /, we can disable the safety feature and delete the entire system using:

rm -rf --no-preserve-root /

The aftermath of this action is that system files like /etc (a place where configurations are kept), /bin (a place where commands like cat and rm are stored), and many other important system files get removed. Programs that were already loaded into memory might continue to work for a while, but new programs cannot start. Because programs depend on other programs, eventually they will all fail. Even after reboot, the system can't boot because the boot files were inside the / directory and were removed in the process.
